# KV 稳态预算默认开：显存验证的原始数据（2026-10-04）

README 第 8 组的数据。方法：1003 的镜像（`heavily-modified-v1-1003-sm70main`），把改过的 Python 文件覆盖上去，用 `sx_tests/kv-steady-budget/run_on_v100.sh --switch auto` 起引擎：每条通道先用 `SX_OPT_KV_STEADY_BUDGET=0` 在第一个 util 上跑一遍作基线，再不设这个变量（默认）在每个 util 上各跑一遍；每次启动、空闲、压测（4 条 8K + 2 条 16K 同时到达，再一条 32K），每 2 秒记录每张卡的 `memory.used`，并检查引擎日志里的错误、显存溢出和自检结论。GPU 4–7，生产 8031 在 GPU 0–3，全程只做健康检查。

| 目录 | 内容 |
|---|---|
| `first-run-graph-reserve-charged/` | **第一版“默认开”的结果（从没发布）**：覆盖的文件是提交 `394ebab54`。不开 MTP 通道在 util 0.90 下 KV 容量从 410,988 降到 325,088 token（−21%），原因是上游风格的 graph 预留（激活峰值，1.10 GiB）又被算进了显存利用率上限，而通道参考值已经包含 graph 池。开 MTP 通道没有受影响（那一路的 graph 预留日志里是 0）。保留作为更正记录。`out-nomtp/`、`out-mtp/` 里每个配置一个目录（`compose.yaml`、`engine.log`、`events.log`、`samples.csv`、`stress.json`）加 `result.*.json` 和 `summary.txt` |
| `final-overlay-run/` | **修正后的结果**：覆盖的文件是提交 `782403821`（两条通道不再重复扣 graph 预留；显式设置的 `VLLM_V2_CUDAGRAPH_MEM_MIB` 仍然生效）。不开 MTP util 0.90 / 0.94、开 MTP util 0.87 / 0.93。其后的提交 `4e888907c` 只把差 64 MiB 以内的自检不足从错误降为警告（该提交没有再单独跑 GPU，显存行为没有变化；发行的 wheel 另做了验证，见 README 第 8 组） |

`summary.txt` 的列：开关（0 / auto = 不设变量）、util、KV 容量、`Available KV` GiB、graph 捕获占用、启动时峰值、空闲、压测时峰值、整体峰值、峰值时 CUDA 剩余显存、自检结论（括号里是自检建议的 `SX_OPT_KV_STEADY_RESERVE_MIB`）、判定。判定的上限是峰值不超过 32,200 MiB、峰值时剩余不少于 500 MiB、没有失败请求、日志没有错误行、自检不报不足。
